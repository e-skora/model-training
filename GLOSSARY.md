# GLOSSARY.md

Plain meanings. Add a term the first time it shows up.

- **AI model:** a program that has learned patterns from lots of examples. You give it text; it gives text back.
- **Parameters:** the model's internal numbers, set during training. "4B" means about 4 billion of them. More parameters usually means smarter but slower and more expensive.
- **Open model:** a model whose parameters anyone can download and change.
- **Base model:** the open model we start from, before our training.
- **Fine-tuning:** training an existing model a bit more on your own examples so it gets good at one job.
- **Supervised fine-tuning (SFT):** fine-tuning where every example shows the exact right answer, and the model learns to copy that kind of answer.
- **LoRA:** a cheap way to fine-tune. Instead of changing all the parameters, you train a small add-on (an "adapter") that sits on top of the model.
- **QLoRA:** LoRA on a squeezed, smaller-memory copy of the model, so it fits on a cheaper GPU.
- **Adapter:** the small add-on file that LoRA training produces. Base model plus adapter equals your fine-tuned model.
- **GPU:** a computer chip that does the math for training fast. We rent them by the second on Modal.
- **VRAM:** the GPU's own memory. The model has to fit in it.
- **Modal:** a service that runs your Python code on rented GPUs and bills by the second.
- **Unsloth:** free, open-source software that makes fine-tuning faster and use less memory.
- **Hugging Face:** the main public website for sharing models and datasets.
- **Model card:** a model's public info page on Hugging Face: what it does, how it was trained, how well it scores, its limits.
- **Dataset:** a collection of examples.
- **JSONL:** a file format with one example per line, each written as JSON (a tidy, standard way to write data that programs can read).
- **Training set:** the examples the model learns from.
- **Test set:** separate examples the model never trains on, used only to score it. Like a final exam the student has never seen.
- **Frozen:** a file that is locked and never changed again, so scores stay fair.
- **Baseline:** the base model's score before our training. Our goal is to beat it.
- **Synthetic data:** made-up examples, here written by an AI model and spot-checked by a person.
- **Contradiction:** two memories that cannot both be true at the same time.
- **Precision:** of all the times the model said "contradiction", how often it was right.
- **Recall:** of all the real contradictions, how many the model caught.
- **Reinforcement learning (RL):** training where the model tries answers, a program scores them, and the model learns to get higher scores.
- **Reward:** the score a program gives each answer during RL.
- **GRPO:** a popular RL method. The model writes several answers to the same question, and it learns from the ones that scored better than the group's average.
- **Ollama / MLX:** two programs that run AI models on your own Mac.
- **Branch:** a separate line of work in git, so changes can be tried without breaking `main`.
- **uv:** a tool that sets up a Python project: it picks the Python version, installs the packages the project needs, and writes them down so every computer gets the same ones.
- **pyproject.toml / uv.lock:** the two files uv writes. `pyproject.toml` lists what the project needs; `uv.lock` records the exact versions installed.
- **Container image:** a ready-made package of an operating system, Python and installed software. Modal starts a fresh copy of it on the GPU machine for each run, so the code always finds the same setup.
- **Modal secret:** a password or token stored safely inside Modal. Code running on Modal can read it, but it never sits in our files or in git.
- **Timeout:** the most time a Modal function may run. When time is up, Modal stops it, so a stuck job cannot run up a big bill.
- **Hugging Face token:** a long password that lets programs act as your Hugging Face account, for example to upload a model.
- **Label:** the right answer attached to an example. Here it is `contradiction` or `non_contradiction`, plus a type for non-contradictions.
- **Spot-check:** a person reads a small random handful of examples by hand, to catch mistakes in the whole set without reading all of it.
- **Random seed:** a number that fixes how a "random" pick or shuffle comes out. The same seed always gives the same result, so anyone can repeat it.
- **Near-miss:** a pair that looks like a contradiction on the surface (same words, a small difference) but is not one, for example an update or two details that fit together.
- **Checker script:** a small program that reads a data file and stops with a clear message if anything breaks the rules, before the data is used.
- **SHA-256 fingerprint:** a long code worked out from a file's exact contents. If even one letter in the file changes, the code changes, so it proves a frozen file was not edited.
- **Shortcut:** a surface pattern that gives the right answer on a test set without real understanding, for example "the word *now* means update". A good test set has none, so a model can only score well by reading properly.
- **Change word:** a word that often signals a change, such as "now", "moved", "switched", "since", "stopped", "later" or "replaced". In the M1 test set these words appear in every label, so they cannot be used as a shortcut.
- **Hard case:** a pair built to fool a shortcut, for example two "now" memories that still contradict, or an update that never uses a change word.
- **Template:** a sentence pattern reused with only a word swapped, such as "X's only bike is red" and "X's only bike is blue". Too many of them make a test set easy to game.
- **System message:** the first message in a chat with a model, which tells it its job and the rules. The person's question comes after it, in the user message.
- **Chat template:** the exact way a model expects a chat to be written out as one piece of text, with special markers for who is speaking. Each model family has its own; the tokenizer applies it.
- **Tokenizer:** the part of a model that cuts text into small pieces (tokens) and turns them into numbers the model can read, and back again.
- **Greedy decoding:** the model always picks its single most likely next word. No dice are rolled, so the same question always gets the same answer.
- **4-bit:** storing each of the model's numbers in 4 bits instead of 16. The model needs about a quarter of the memory and gets only a little less accurate. QLoRA trains on top of a 4-bit copy.
- **Thinking model:** a model that writes out its reasoning (inside `<think>` tags) before it answers. Qwen3-8B is one; we turn thinking off so it answers straight away.
- **Pin:** writing down an exact version of a package (for example `unsloth==2026.10.7`) so every run installs the same one.
- **Smoke test:** a tiny first run (here 8 pairs instead of 200) to catch obvious breakage cheaply before the real run.
- **Invalid answer:** a model answer the scorer cannot use, because it is not JSON or uses a label that does not exist. It is neither a "yes" nor a "no": it lowers recall (when the right answer was contradiction) and accuracy, but not precision.
- **Format error:** an answer with a readable label that breaks the prompt's other rules, for example a contradiction whose type is not `null`. Counted on its own; it does not change the label scores.
- **num_beams:** how many candidate answers the model builds side by side before picking one. `num_beams=1` means one, which together with no sampling is greedy decoding.
- **Revision (commit):** the exact saved version of a model's files on Hugging Face, named by a long code. Loading the same revision gives the same files every time.
- **False alarm:** the model says "contradiction" when there is none. False alarms lower precision; missed contradictions lower recall.
- **Validation set:** a small set of examples kept apart from the training set and checked now and then during training, to see whether the model is still learning the rule or only memorising. The model never trains on it. Ours is `data/m1/valid.jsonl`, 99 pairs.
- **Overfitting:** when a model memorises its practice examples instead of learning the rule behind them. It keeps getting better on the training set but gets worse on new examples, like a student who memorised last year's answers.
- **Unclear (label):** the third answer the judge may give when the two memories alone cannot settle whether they clash, because it depends on a fact neither gives. Aeverum turns it into "needs manual review" instead of a guess.
- **Swapped / no-dates versions:** two copies of the frozen test set made in memory, never saved: one with the two memories in the other order, one with the dates removed. They check that the judge does not depend on order or dates.
- **Near copy:** a pair that shares more than 60% of its words (leaving out the person's name) with another pair. The checker stops if a training pair is a near copy of a test pair, so the model cannot score well by remembering.
- **Prompt fingerprint:** the SHA-256 of the prompt's fixed text. If anyone changes a word of the prompt, the fingerprint changes, so a score can always be tied to the exact prompt that produced it.
- **Stratified split:** taking a sample so that each group (here each label and type) keeps its share, for example 45 contradictions in 100 validation pairs because the whole set is 45% contradictions.
- **Exclusive word:** a word that rules out other cases, such as "only", "always", "never" or "every day". "Works from home on Fridays" and "works from home on Mondays" can both be true; "works from home only on Fridays" and "works from home on Mondays" cannot (reading rule 5).
- **Loss:** the model's error score while it trains: how surprised it is by the right answer. Lower is better. Training pushes it down.
- **Training loss / validation loss:** the loss on the pairs the model learns from, and on held-back pairs it never learns from. If the training loss keeps falling while the validation loss rises, the model is memorising instead of learning (overfitting).
- **Epoch:** one full pass through the training set. Our run did 3 epochs of 1,522 pairs.
- **Step (training step):** one small update of the adapter, after the model has seen a few examples (here 16, the batch).
- **Batch size and gradient accumulation:** how many examples the model sees before one update. We use 4 at a time, 4 times over, so each step learns from 16 examples.
- **Learning rate:** how big each update is. Too big and training jumps around; too small and it learns slowly. We used Unsloth's suggested 2e-4 (0.0002).
- **Warmup:** the first few steps use a smaller learning rate that grows to the full one, so the very first updates do not knock the model off course. Ours: 14 steps (5%).
- **Weight decay:** a small pull that keeps the adapter's numbers from growing too large, which helps against overfitting.
- **LoRA rank (r) and alpha:** the size of the LoRA adapter (r) and how strongly it counts (alpha). We used r = 32, alpha = 32, as in Unsloth's notebook for this model.
- **Train on responses only:** the model is graded only on the answer it should give (the JSON), not on the prompt it was shown. The prompt's tokens are masked: marked "do not grade".
- **Mask:** a mark on each token that says whether it counts for the loss. Our check proves, for every training row, that only the answer and its end token count.
- **End-of-turn token:** a special token (here `<|im_end|>`) that means "my answer is finished". The model is trained to write it, so it stops after the JSON.
- **Checkpoint:** a saved copy of the adapter at one moment of training, here after each epoch.
- **Trial run:** a short training run (here 20 steps) to measure speed and memory and catch errors before paying for the full run.
- **Modal volume:** a folder that lives on Modal between runs. The adapters wait there until the chosen one is uploaded.
- **Adapter upload:** sending the trained adapter files from Modal to a Hugging Face repo, so later steps (and later, other people) can load them. Ours goes to a private repo, which only Elias's account can see, until Step 9.
- **Private repo:** a Hugging Face repo that only its owner can see. Without a login, Hugging Face answers "not allowed" (401).
- **Empty think block:** `<think></think>` with nothing inside. Qwen3's chat template adds it to a whole conversation, but our model never thinks out loud, so it is left out of the training text.
- **Inferred (a claim):** worked out from evidence, but not seen directly in a record. "The baseline most likely loaded the same files" is inferred; "training loaded these files" is recorded. (Not to be confused with *inference*, which also means a model answering.)
- **GGUF:** a model saved as one file, ready for llama.cpp and Ollama to run on an ordinary computer. It holds the model's numbers, its tokenizer and its chat template.
- **llama.cpp:** free software that runs language models on ordinary computers, including Macs, without a big GPU. It also has the tools that turn a model into a GGUF and shrink it. Ollama uses the same file format.
- **Ollama:** an app that runs models on your own computer and answers questions on a local web address (`http://127.0.0.1:11434`), so other programs on the Mac can ask the model things.
- **Modelfile:** Ollama's recipe file for a model: which GGUF to use, which chat template to wrap messages in, and settings such as temperature. Ours is `ollama/Modelfile`.
- **Chat template:** the exact wrapping text a model expects around each message, such as `<|im_start|>user` before a question and `<|im_end|>` after it. A model trained with one template can give broken answers with another.
- **Quantization:** storing each of the model's numbers with fewer bits, so the file is smaller and runs faster, at the cost of a little accuracy. Like saving a photo at lower quality.
- **q4_k_m:** a common quantization setting from llama.cpp: about 4 bits for most numbers, a bit more for the ones that matter most. Our 4-billion-parameter judge shrinks from about 8 GB to 2.5 GB.
- **Merge (an adapter):** adding the trained adapter's changes into the model's own numbers, so base model and adapter become one model that needs no add-on.
- **16-bit weights:** the model's numbers at full working precision (about 8 GB for our model). Unsloth merges the adapter into these, not into the 4-bit copy used for training, then quantizes the result.
- **Label agreement:** the share of pairs where two versions of the judge give the same label. Step 8 needed at least 97% between the Mac file and the trained adapter on Modal.
- **Greedy answers (temperature 0):** the model always picks its most likely next word, so the same question gets the same answer every time.
- **Dataset card:** a dataset's info page on Hugging Face (its `README.md`): what is in it, how it was made, its counts, fingerprints, license and limits.
- **Card metadata:** the short block at the top of a model or dataset card, between two `---` lines, that Hugging Face reads: license, base model, language, tags, and for a dataset which file is which split.
- **base_model:** the card metadata field that names the model this one was made from. Hugging Face uses it to link the two and to show "fine-tuned from" or "adapter of".
- **CC BY 4.0:** a license for data and writing: anyone may use it for anything, including paid work, if they credit the author. Our dataset uses it.
- **Apache 2.0:** a license for software and models: anyone may use, change and sell it, if they keep the license notice. Qwen3-4B uses it, so our models do too.
- **Pre-publish check:** `scripts/prepublish_check.py`. Before anything goes public, it looks for secrets, model files in git, em dashes, personal data and numbers in the cards that do not match the results. It changes nothing; it only reports.
- **Round half up:** rounding where an exact half goes up, so 0.965 becomes 0.97. Python's usual rounding of decimals can give 0.96 instead, because 0.965 is stored as a hair less than 0.965.
- **GRPO (Group Relative Policy Optimization):** a reinforcement learning method. For each question the model writes a group of answers, each answer is scored, and the model is pushed toward the answers that scored above the group's average.
- **Reward:** the points a program gives one answer during reinforcement learning.
- **Reward function:** the small program that gives the points.
- **Reward hacking:** when the model finds a cheap way to score points without doing the real job, for example always giving the safest answer.
- **Hard test set:** a test set written on purpose from tricky cases (traps), so that real gains show up and are not lost in luck.
- **Trap:** one kind of tricky case, such as a contradiction a reader could explain away. Each hard test pair is tagged with its trap.
- **Temperature:** how much randomness the model uses when it picks words. 0 always picks the most likely word (the same answer every time); 1 lets it vary, which RL needs so its answers differ.
- **Thinking mode:** some models write their reasoning before the answer. Qwen3-4B-Instruct-2507 has no thinking mode.
- **Name wall:** a check that no person's name from one data file appears anywhere in another, so a test set never shares people with the data a model trained on.
- **Blind review:** a second reviewer answers each pair before seeing its label, then compares. It catches wrong or unclear labels that the writer would read past.
- **Per-trap score:** precision, recall and `unclear` counted for each trap on its own, so you can see which kinds of tricky case a model gets wrong.
- **Worst case (a score):** the lowest of a model's three scores on the as is, swapped and no-dates versions of a test set. M2's bar is set on it, because Aeverum may send pairs in any order and without dates.
- **`unclear` dodge:** an `unclear` answer on a pair the text does settle, usually with a made-up way out ("fear of dogs can be mild or strong"). It counts as a miss on a real contradiction.
- **Wall time:** how long a run took from start to finish as seen from the Mac, including waiting for a GPU and starting the container. Modal bills the time the container loads and answers, so wall time is an upper bound on the cost.
- **Provenance fields (`source`, `label_by`):** two fields on every new data row that say where it came from (`synthetic` means made up) and who set its label (`claude-code`), so a later model can mix made-up and real-verdict rows knowingly.
- **`true_unclear`:** the trap tag for a training pair whose right answer really is `unclear`: one fact that decides it is missing, and both readings are equally natural.
- **Mixed-in pairs (in a blind review):** ordinary pairs with known labels, hidden among the pairs being tested, so the judge cannot guess which are which, and so you can check that the judge is not simply giving one answer to everything.
- **RL pool:** the pairs GRPO trains on. M2 keeps a pair only if v1's 8 tries at it score differently, plus a few pairs v1 always gets right (D-046). File: `data/m2/rl-pool.jsonl`.
- **Mixed pair:** a pair where the model's 8 tries got different points. Only these teach GRPO something, because GRPO learns from the difference between tries.
- **Always right / always wrong (a pair):** all 8 tries got the same points, with the right label every time, or with the same wrong answer every time. An always-wrong pair may have a wrong label, so it is checked before any training.
- **Sampled accuracy:** the share of a model's random tries (temperature 1.0) that give the right label. It is lower than the greedy score, because random tries sometimes pick a less likely answer.
- **Reward fingerprint:** `judge.reward.reward_sha256()`, a SHA-256 of the reward table and all the code that reads and scores an answer, found by following every name that code uses (helpers, allowed types, the code-fence pattern, how a training answer is read). Any change to a number, a rule or what counts as valid gives a new fingerprint, so a training run can record exactly which reward it used.
- **num_return_sequences:** a setting that makes the model write several answers to the same prompt in one go. The pool sampling uses 8.
- **top_p, top_k:** two settings that limit which words the model may pick from when it answers with randomness. `top_p` 1.0 and `top_k` 0 mean no limit, so only the temperature shapes the randomness; these are TRL's GRPO defaults.
- **Out of memory (GPU):** the graphics card ran out of room for the numbers it holds while answering. Writing fewer answers at once fixes it.
